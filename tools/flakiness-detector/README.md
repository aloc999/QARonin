# flakiness-detector

Python stdlib-only CLI that classifies tests as **stable**, **flaky**, or
**broken** by comparing their outcomes across N repeated JUnit XML files
(from repeated CI runs).

## Classification math

For each test, the outcome history across runs (in file order) is examined:

- `stable` - passed in every run.
- `broken` - failed in every run.
- `flaky` - outcome mixed or flipped between consecutive runs. Flip rate is
  `flips / transitions` where transitions = `runs - 1`
  (e.g. `[P,P,P,P,F]` -> 1 flip / 4 transitions = 0.25; alternating
  `[P,F,P,F]` -> 3/3 = 1.00). A mixed history with zero consecutive flips
  (a regime change like `[F,F,T]`) is classified flaky with rate 1.0.
- `insufficient-data` - fewer than `--min-runs` observations (skipped tests
  are excluded from histories entirely).

## Usage

```bash
# report from a glob of junit XMLs (order matters: oldest first)
python3 flakiness_detector.py "artifacts/run-*.xml"

# gate CI: exit 1 when any test is flaky (and/or broken)
python3 flakiness_detector.py "artifacts/run-*.xml" --fail-on-flaky --fail-on-broken

# require at least 5 observations before classifying
python3 flakiness_detector.py "artifacts/run-*.xml" --min-runs 5

# write markdown to a file instead of stdout
python3 flakiness_detector.py "artifacts/run-*.xml" -o flake-report.md
```

Options:

| Flag | Meaning |
|------|---------|
| `inputs` | one or more JUnit XML paths, globs, or directories (dirs are scanned for `**/*.xml`) |
| `--min-runs N` | minimum runs before a test is classified (default 2) |
| `--fail-on-flaky` | exit code 1 if any test is flaky |
| `--fail-on-broken` | exit code 1 if any test is broken |
| `-o/--output FILE` | write the markdown report to FILE |

Self-test on bundled fixtures (2 of 6 synthetic tests flip):

```bash
python3 flakiness_detector.py "fixtures/run-*.xml"   # human-readable report
python3 -m pytest tests                              # unit + e2e tests
```

## Fixtures

`fixtures/run-{1..5}.xml` are synthetic runs generated by
`scripts/make_fixtures.py`. Intended classification:

| Test | History | Class |
|------|---------|-------|
| `tests.api::test_login_flow` | PPPPP | stable |
| `tests.api::test_checkout_order` | PPPPP | stable |
| `tests.ui::test_search_products` | PFPFP | flaky (rate 1.00) |
| `tests.ui::test_add_to_cart` | PPPPF | flaky (rate 0.25) |
| `tests.reports::test_admin_report` | FFFFF | broken |
| `tests.api::test_new_feature` | PP (runs 4-5 only) | partial-history handling |

## CI integration

A weekly scheduled job in `.github/workflows/ci.yml` (`flakiness-scan`) runs
the detector over retained junit artifacts when available, and always runs a
smoke pass over the bundled fixtures so the tool itself stays exercised.

Policy: treat flip rate >= 0.25 as actionable - quarantine per the flaky
policy in [strategy/TEST-STRATEGY.md](../../strategy/TEST-STRATEGY.md).
